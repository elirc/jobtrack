# 06 — Contribution Practice

A backlog of realistic work at three levels, plus refactor katas. Every item follows
contribution realism: why it's useful, why the blast radius is small, what pattern it
follows, how it's tested, and what would make a maintainer reject it.

| File | Contents |
|---|---|
| [01-good-first-tickets.md](01-good-first-tickets.md) | 15 junior tickets |
| [02-mid-level-feature-tickets.md](02-mid-level-feature-tickets.md) | 10 cross-layer tickets with design notes required |
| [03-senior-build-projects.md](03-senior-build-projects.md) | 5 projects, 2 days–3 weeks |
| [04-refactor-and-design-katas.md](04-refactor-and-design-katas.md) | 6 katas with self-grading criteria |

Workflow for every ticket: read the anchors → write the test that should fail → implement →
`npm test` green → self-review against [07/01](../07-career-and-collaboration/01-code-review-mindset.md) →
write the PR description per [07/02](../07-career-and-collaboration/02-writing-prs-and-rfcs.md).
Each ticket's **Interview story potential** line feeds
[08/06-behavioral-star-stories.md](../08-interview-prep/06-behavioral-star-stories.md).
